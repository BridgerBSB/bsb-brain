# 2026-08-14

## For future Claude
A table does not clip. Neither matplotlib's `ax.table` nor plottable truncates an overflowing cell - it draws straight through the divider and over the value next door - so a column width is an unenforced assumption about the longest string, and the only symptom is pixels.

## Friction
- Used PowerShell here-string syntax (`@'...'@`) inside the **Bash** tool, which put a stray `@` in a commit subject. Force-push is blocked by branch protection, so it could not be amended away. `windows-toolchain.md` already warns the two shells take different syntax.
- A `python - <<'PY'` heredoc died on `SyntaxError: truncated \UXXXXXXXX escape` because a Windows path (`C:\Users\...`) sat inside a non-raw triple-quoted string. Use `r"""` for any block containing Windows paths.
- Two worktrees were behind origin and refused the push. `git pull --rebase --autostash` handled it and restored the unrelated unstaged files intact.

## Notes & ideas
- The out-of-figure half of the guard is the interesting one: `bbox_inches="tight"` grows the canvas around a runaway label, so the saved PNG looks clean and the fixed-size PDF page is what clips. **Looking at a render is structurally unable to catch it.** That is a genuine limit of blocking rule #18 and the reason the measurement rule now sits beside it.
- Guard coverage is partial and said so out loud: 4 surfaces geometry-checked; anything needing a real `pitch_df` is covered by the source check only. Extending it means synthesising a pitch_df.
