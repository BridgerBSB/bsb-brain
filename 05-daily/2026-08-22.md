# 2026-08-22

## Session - hiring board goes multiplayer, and User Management ships

Repo `C:/Users/Owner/hiring`, branch `main`. 16 commits, all pushed. 280 tests
(was 210). Recall session `2b36`, checkpoint `f1bca9513dc5e3c5`.

Started by recovering a session that died to a machine crash at 06:42. Nothing
was lost - the transcript was on disk and so was a pristine copy of the file
mid-edit. Cost: about 2.5 minutes of work past the last commit.

### What shipped

- **The board stops living in one browser.** Migration 004 applied to production
  Supabase; `board_doc` + `board_blob` created; confirmed saving live. Three-way
  merge per field, so two people editing different things both survive.
- **Shareable URLs** and the browser's own Back button.
- **The accounts became the single list of people.** There were two lists and
  nothing connected them - adding an account did not make somebody assignable.
- **`/admin/access` (User Management)** - owner-only, adds staff, sets levels,
  removes and restores, mails a first password and forces a change.
- **Three areas** instead of five tiles: Hiring Board / Cage Assessment / User
  Management.
- **Private notes became one person's**, withheld by the server.

### Decisions Zac made

- Every account is owner or admin except viewers; only he and Sam are owners.
  The **only** thing an owner can do that an admin cannot is change a level - so
  inviting a candidate moved from owner to admin.
- Viewers are the candidates. Permanent sample viewers live in `admins`;
  temporary candidates live in `invites` and expire on their own.
- Private notes are an individual's own. "Only they can see."
- The blind hold-out should be real: submit yours, then you see everyone's.
- Full names on the evaluation rows, not initials.

### Worth remembering

- **A label is not a mechanism.** Three separate things today claimed something
  the code did not do: the blind hold-out (`isAdmin()` was permanently true),
  private notes (one shared string), and acting-as (stored in the shared
  document, so one person's choice became everyone's). All three were found by
  asking what values each side of a comparison can actually take.
- **I shipped a feature completely inert and said it worked.** `data-mynote`
  maps to `dataset.mynote`; camelCase needs a hyphen. I had "verified" it by
  calling the accessor functions directly and never touched the textarea - the
  engine bench-tested with the throttle cable on the floor. The code review
  caught it. **Drive the real element, not the function behind it.**
- **I told Zac the backend was done before checking the live database.** True of
  the code, false end to end - the tables did not exist. He pushed back and was
  right to.
- Deliberately breaking a new guard is worth the two minutes. It caught a
  last-owner check that could never fire, and was wrong in the one case where it
  could.
