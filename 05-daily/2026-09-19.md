# 2026-09-19


## Command CV — the pull pipeline, and five silent defects

Scaled the ball-detector dataset from 4 ballparks to **13**: 19 park-games,
2,983 clips, **31,699 labelled points** against 2,136 in all of v1. 25 commits.

Built the whole chain: `affiliate_schedule.py` enumerates 700 games across
**63 level-venues** (348 of them away) off the PUBLIC schedule endpoint, no auth.
`harvest_pull_csvs.py` does the authed half in Python and banked 4,813 clips.
`rolling_pull.py` downloads, detects, labels, cuts crops and deletes the video,
so disk stops being the constraint.

**Token facts, all measured.** The browser session alone returns 401. There is
NO refresh token — the app never requested `offline_access`. But the mp4 URLs
need no auth at all and do not expire, which is what makes unattended (and
Colab) work possible.

**Five silent defects, four of them mine.** None produced an error:
1. The pose was vetoing good detector tracks — 81 of 212 Isotopes clips.
2. The scan window was truncating flights — Greensboro's plate is f277 against
   a window ending f250. Constellation 31% → 47% from that one change.
3. My `--angle` default was CENTERFIELD, so two venues came down in a geometry
   the detector has never seen.
4. A documented cv2 seek bug reappeared in fresh verification code and made
   nine parks' labels look wrong when they were fine.
5. The loop deleted video before cutting crops, so pruned games' labels could
   not become training data.

Three of the four were caught by an artifact that prints its own denominator:
the scoreboard showing "15900%", the builder showing `skipped: 1305`, the sheet
drawing circles beside balls.

Also **retracted** a claim I made in a commit — "low-yield parks share tight,
low framing". Never measured it; corr(yield, ball size) is +0.52, the opposite.
