# 2026-08-09

## AstrosEDU quizzes, page sections, batch upload (astroworld-dev)

Long session, 14 PRs, and one self-inflicted outage.

**Built:** quizzes end to end (authoring, server-side grading, gating, unlimited
retakes with best score, a results page) - Zac verified it live, 100% on the
second try. Then page sections, so Our Culture splits into Mission / Core
Pillars / Our Culture Defined. Pitching and Baserunning restructured to his
lists, plus Player Plan Process and Our Culture as Programs buttons. Batch
upload: pick the page once, drop N files, set title/type/section per file.
And no size limit anywhere any more - both upload screens send 4 MB chunks now.

**The outage.** Merging page sections took every page read in the app down. The
cause was a duplicated fact: the admin Database page had its own copy of the
"is this migration applied" logic, checking only tables with `creates.every()`.
A columns-only migration has an empty `creates`, and `[].every()` is true - so
it reported itself applied on the very screen used to apply it, the button sat
disabled as Done, the migration never ran, and Prisma then asked for a column
that did not exist on every query.

Worse than the bug: I had fixed that logic in the API route hours earlier, told
Zac the status was trustworthy, and never checked which code path actually
rendered the screen. He merged on my say-so and the site went down. He was
right to be angry.

**What I take from it:** a schema change and its migration cannot ship in the
same PR - declaring a column makes the generated client request it everywhere
immediately, before anyone can apply anything. And never permanently disable
the button that fixes the problem.

**Zac parked two things,** both about the upload UI: no thumbnail field on the
batch screen, and he prefers the batch row layout enough to consider it for the
single form too.

**Three things I raised that he has not answered** - storage driver still
`local` while he loads video, no finish state when a course completes, and
`BOOTSTRAP_ADMINS` possibly unset. None are declined, just unanswered.
