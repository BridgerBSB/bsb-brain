## Postgame V2 — tabs 4-6 (Location / Pitching / Glossary)

Built the last three tabs of the V2 card and then spent most of the session
correcting them, which is the honest summary.

**The one worth remembering:** Location and Pitching both negated `plate_x` on
a frame `enrich_pitches` had already negated, so every panel was mirrored —
inside to a righty drew as outside. **Both test suites certified it**: each
built a fixture it called "catcher's view", a frame no caller ever produces,
and asserted the output was negated. Zac caught it by looking at the tab.
Fourth instance of that column. The fix that matters is the naming one —
`_to_pitcher_view(x)` says what it DOES so it reads as correct at every call
site; `game_plate_x` / `season_plate_x` say what they are FOR, so a wrong call
site reads wrong. The negating helper is deleted outright.

**Second:** the Glossary deduped on the internal metric key, so `whiff_pct`
and `whiff` were two things to the code and one word to the reader. Whiff%,
Z-Whiff%, CSW% and Barrel% each printed twice. Zac caught it twice, the second
time angrily and fairly. Now deduped on the printed label. The subtlety is
that the naive fix is also wrong: `vR` appears on three tabs as three
different metrics, so it must NOT merge — it is qualified instead.

**pBarrel:** the Performance Contact block had been showing pBarrel under the
label "Barrel%" since August while the Pitching tab showed the real MLB
barrel. I documented that as a known collision in the glossary instead of
treating it as the instruction violation it was. Writing a careful note about
a rule being broken is not following the rule. Fixed, with its own pool.

### Zac, verbatim, worth keeping
- "we should never use pbarrel% unless i explicilty ask for it" — and later,
  clarifying: inside a GC2-sanctioned metric (gcERA, gcPerf run value) is
  fine, it is standalone use he does not want.
- "forget splitting them by section - why the fuck are terms repeated"
- On the multi-level pool question: "well yeah here we will leave that
  potentially open".
- On the finished glossary: "looks fantastic tbh… absolutely beautiful".

### Decided
- Pitching heatmap stays treatment **A** (smoothed value surface, alpha =
  density) — he picked it from four rendered variants because it feels like
  the other apps. GC2's own count grid can flood the whole panel because it is
  a fitted model; ours is an empirical average, so filling everywhere would be
  inventing.
- Pitching surface = his SEASON, dots = the SELECTION (V1 LVA parity).
- Empty cells draw nothing; the slot stays so columns align across hand blocks.

### Left open, on purpose
Whether V2 should rank a mixed-level selection against a COMBINED pool to
match the trackers. Verified cheap — pools are sorted lists, so it is
concatenation, no re-pin — but it reverses his 09-01 "use the current level"
call, so it needs a yes first.
