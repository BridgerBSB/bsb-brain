## Session - EOY report: inline render, then the pinning reality check

Made the EOY position deck actually visible in the app. It was a
"Generate PDF preview" button plus a download link, so you could not see the
report without leaving Streamlit. Now selecting a player auto-renders all 22
pages inline (pymupdf -> st.image), the way advance scouting shows its work.
Preview button deleted.

Split the build at a seam that matters: **only page 1 reads the coordinator
notes**, so the ~43 season queries cache on the player alone. Typing notes never
re-queries, and changing how a page looks never invalidates it - only adding or
removing a page does.

Then built the payload pin and Zac ran it. **152s per player, 5.7 hours for 135,
~45 MB.** Size was never the risk; runtime is. Killed at 10/135.

**Root cause:** eoy_fielding_data / eoy_catching_data / eoy_br_data have ZERO
caching between them (31 run_query calls), and those queries are league-wide
POOLS - several hardcoded to the MLB pool, so it is ONE query re-executed 135
times.

**The finding worth keeping:** the intangibles fielding tracker pin already holds
`raw_tdm` = one row per TDM event with every tracking metric. It has no
direction. Adding it is one join + one column - it does NOT multiply rows.
That would make directional + positional metrics a groupby over a pinned frame
everywhere, which is exactly what Zac wants across the intangibles trackers.

**Zac said:** wants to `/discuss` then `/spec` this with fresh context, not at the
tail of a long session. Decision on the table: one column on `raw_tdm` vs a
separate directional pin. He leans toward adding positional + directional metrics
to all the affiliate trackers and having EOY pull from them.

Also fixed along the way: the affiliate logos were never in `manifest.json` so
Connect silently drew text chips while the CLI looked fine; `pins_config` never
passed `allow_pickle_read=True`, so any joblib pin read from pd-goals would have
raised.

**Two runbook lessons I got wrong:** handed him a command with `<key>` angle
brackets (PowerShell parses `<`; windows-toolchain.md already says not to), and
gave a `pd-goals\scripts\...` path to run from inside `pd-goals`, which he hit
twice.
