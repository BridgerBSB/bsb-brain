
## EOY note line breaks + the S&C bodyweight load

**The defect.** A coordinator typed an off-season goal as two lines and the
delivered deck drew it as one. `textwrap.wrap` defaults to
`replace_whitespace=True`, so every newline and tab became a space. The pin
held the text correctly and the app's own box redisplayed it correctly — the
**only** surface that showed the bug was the deck already sent to a player.
That is the lesson worth keeping: when a value looks right everywhere you
normally look, go render the thing the reader actually receives.

**Shipped.** `src/eoy_text_block.py` is now the one path every EOY note box
takes; it replaced four independent wrap idioms, one of which happened to be
right. Paragraphs survive, typed indents keep a hanging wrap, long notes fit by
stepping the font *down* rather than being ellipsized. App redeployed, live,
Zac confirmed.

**Then the loader.** 186 off-season bodyweights into Goal #1 on page 2 of both
decks — 154 written and verified, 10 held for manual entry. Zac: *"this process
is fine and we may need to do this same thing in the future."* Captured as
`.claude/rules/bulk-load-into-a-pin.md`.

**The spreadsheet was wrong three ways at once.** A label column had been
dragged with the fill handle, so Excel incremented the number inside it — row 3
read `2026 End Weight:` and row 188 read **`2211 End Weight:`**. 185 of 189 rows
wrong. Four more cells hadn't recalculated and were displaying another player's
values. Row 3 was the one correct row, and it was the row in the screenshot
everyone validated against.

**Three things I got wrong, in order.**

1. Read an IT whitelist refusal as a broken pip shim, and wrote 40 lines of
   resolver into five deploy scripts to route around it. Zac's screenshot of
   the actual dialog settled it. Reverted whole — routing an IT policy isn't
   ours to decide. `No process is associated with this object` means the launch
   was *refused*, and I should have taken that at face value.
2. Asserted a repeated end weight was a broken lookup. Camden checked: real
   data. Eighteen groups in that sheet share a value, because round baseball
   weights repeat. Killed the "duplicate value detector" idea it suggested — it
   would fire constantly on clean data.
3. Generated the corrected extract into my own Downloads and handed over a
   command containing a literal `C:\path\to\` placeholder, which got pasted
   verbatim. Fixed by committing the CSV to the repo and making it the default.

**Zac's calls.** ML players stay in — *"they may be mislabelled, those guys jump
up and down from AAA to the big leagues"* — so `level_code` is a snapshot of
current assignment, not an identity, and must not be used as a filter.

**Still open:** `rsconnect.exe` needs a **standing** IT approval, not a
per-invocation code; every Connect deploy is gated behind that dialog. And the
Connect API key was pasted in plaintext in terminal output — flagged twice for
rotation, not confirmed.

## Session - the case assessments become a generated deck (hiring, session `afa8`)

Spent the day turning the Director of Hitting and Director of Pitching case
assessments into something a generator builds, with Zac dictating the wording
page by page. Hitting is 14 slides, pitching is 9. Nobody edits a PPTX; the
content is JSON and the deck falls out of it.

**The lesson that keeps repeating: rendering is the only test of a layout.**
Three separate defects this session were invisible to the code and obvious in
the picture. `line: { width: 0 }` does not suppress PowerPoint's default
outline, so every hairline drew near-black. The title band left a white gutter
at the bleed edge. And on the pitching Environment page every question row was
the same height, so a three-line question filled its row and sat flush against
the next one while one-line questions had an inch of air under them, one word
from clipping. Nothing but a render shows any of that.

**A guard caught its own author.** The house-rule check on em dashes and
non-ASCII failed the very first build, on a middot I had put in my own eyebrow
strings.

**Sam's feature request was not a feature.** He asked whether new sections
could be added to the board. They already could - Settings > Hiring Roles has
had a working "+ Add Hiring Role" since release, cloning an evaluation template
and a question bank. Nobody found it because the place you look for "add
another one of these" is beside the ones you can already see. So the fix was a
doorway, not a build: one tile on the dashboard calling the same function. Then
I verified it by clicking the real element in a headless browser rather than
calling the function, which is the exact mistake that shipped private notes
inert last week - and worth it, because my first probe read `body.innerText`
and wrongly reported the heading missing. innerText is layout-dependent in
headless; a DOM query is not.

**The signed-out page.** An expired session opening `/admin/hiring` was shown
`{"error":"Not signed in.","status":401}` as the page. The interesting part was
resisting the obvious fix: every `/admin` route already carries its own
dependency, and adding a middleware gate would have created a second authority
on access. Changed how the refusal *renders* for a browser navigation instead,
so there is still exactly one thing deciding who gets in. Sending someone to
`/login` then meant sending them back, and a `next` with no guard is an open
redirect, so `safe_next` got tested harder than the happy path.

**Read all six HTKCH PDFs**, 185 pages. Hitting Biomechanics is the movement
document by a distance; Programming/Swing Flaws is the most operational, with
eight named flaws each carrying a camera view and a visual marker; Big 3 has
the least movement but holds the trainability table, which is the direct answer
key to the tenets follow-up. The rule that governs all of it: substance goes in
the never-send evaluator kit, the source is never named on a slide.

**Two things to remember Zac said.** The grey italic lead lines I had written
over his questions were "corny" and editorialised them - they were mine, not
his, and they are gone. And when he asked where the PPTX was, the answer was
that I had built it fifteen minutes earlier and handed him a repo path instead
of putting it where he would actually pick it up. Deliverables go to Downloads.

Ended by prepping the next build rather than starting it: the PD Calendar spec
is written against how the hiring board is actually wired, and it says
explicitly which part of the board NOT to copy.
