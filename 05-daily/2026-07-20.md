## Wins
- Zac's diagnosis was inverted ("the stapler fires too soon") — the stapler had
  never started. The barrier was correct; the bug was that it blocked
  *everything*, not just the stapler. Worth stating plainly rather than
  validating the premise.
- Every fix was tested with real processes rather than reasoned about, and that
  caught **three wrong assumptions of mine**: `Stop-Job` DOES kill python
  grandchildren; orphans come from Ctrl+C never calling `Stop-Job` at all; and
  `return ,$arr` nests the array at the `@()` call site so `.Count` silently
  reads 1 forever — which would have disabled both the guard and the sweep.
- The test harness accidentally reproduced the production bug: `"$env:TEMP\c$_.log"`
  parses `$_.log` as property access, so 3 jobs shared one log path and 2 died
  instantly — exactly what `of-kpi`/`pitcher-kpi` did on the work laptop.
  Independent confirmation of the shared-handle diagnosis.
