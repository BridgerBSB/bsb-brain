
## Session - hiring multipurpose app (rubric base, 8 pack, MNFA)

**The two findings worth keeping.**

1. **Coordinator was never a legal value in the database.** `admins_role_check`
   was written in migration 002 and widened once in 003; coordinator arrived in
   August and nobody widened it again. Every "Set level -> Coordinator" raised a
   check violation, and both routes wrapped the call in a bare `except` that
   printed "That action did not complete" - naming the app while the database
   refused a VALUE. 554 tests were green because they all run SQLite, which has
   no check constraint on that column at all.

2. **Pot. MNFA was stored the whole time.** The roster query derived it on the
   stated grounds that no column held it - true, ZERO columns match `mnfa`. Two
   match `mnlgfa`. eBIS spells it MN-LG-FA, on a table we already joined for
   birth_country. The derivation was right 79 of 289 times. Zac guessed the
   cause of the two blank players (acquisition) and so did I, and we were BOTH
   wrong - the file's own elapsed-projection rule suppressed them.
