# In-App Submission Pattern — Form → Pin → PDF → Slack

Reusable architecture for Streamlit apps that accept user input and deliver
a branded PDF to Slack **entirely from inside the running app on Posit
Connect**. No CLI, no external infra, no IT request.

Pioneered on **Transition Report** in PD Engine (Apr 23-24, 2026). Use this
when building any future internal form (incident reports, player move
tracking, weekly coach notes, scout reports, anything questionnaire-shaped).

---

## 1. Why this pattern exists

Historically, every Slack-delivered PDF in this repo was generated by a
batch CLI run from the work laptop (`scripts/generate_*.py --deliver`).
That works for nightly reports, but it's the wrong shape for anything
user-triggered: a coordinator shouldn't have to SSH into a laptop to
submit a questionnaire.

Posit Connect has everything needed to do the whole flow in-process:
- Parquet pins for persistent writable storage (survives container restarts)
- Outbound HTTPS (Streamlit can `requests.post` to anywhere)
- The same Azure Logic App endpoint the CLIs already use

So: submit button → pin write → PDF render → POST to Logic App → Slack.
All inside one Streamlit request. ~5 seconds end-to-end.

#### Dynamic heights + page-2 spillover (BLOCKING for any free-text PDF)

Coaches type arbitrary-length answers. **NEVER use fixed sub-block heights** —
short text gets cramped, long text gets truncated with ellipsis. The
canonical pattern (shipped May 25 2026 in `transition_pdf.py`, commits
`1d7c6f7f` + `bca7beb8`):

1. **Measure first, draw second.** Add a `_wrap_lines(c, text, max_w, font, size)`
   helper that returns the wrapped line list WITHOUT drawing. Used by the
   measurement pass to compute each block's required height from actual
   content.
2. **Compute section heights from content.** For grids of N sub-blocks:
   `section_body_h = max(left_side_total, right_side_total) + section_padding`.
   Pass per-sub-block heights down via an optional `sub_heights=` kwarg on
   the subcard drawer so each block gets exactly the room it needs.
3. **Spill to page 2 when total exceeds page budget.** Compute
   `available_h = top_y - MARGIN - 12`. If `total_needed > available_h`,
   draw the most important rows on page 1, call
   `_draw_outer_card_border(c)` to finalize page 1's frame BEFORE
   `c.showPage()`, then redraw chrome (`_draw_board_background` +
   `_draw_outer_card` + `_draw_header`) on page 2 and draw remaining
   rows. Caller's terminal `_draw_outer_card_border(c)` then lands on
   page 2 (the current page), giving both pages a clean border.
4. **Sanity-cap section_h at available_h.** If even one row's content
   alone exceeds available_h, scale sub-block heights proportionally
   (rare — would take >1500 chars per side to hit).

##### Float-precision gotcha (BLOCKING — the lesson from May 25 2026)

The wrap-renderer takes `max_h` and computes
`max_lines = int(max_h // line_h)`. If the measurement budgets exactly
`n * line_h` for n lines but IEEE float subtraction drifts max_h down
to `n * line_h - 0.000...006`, then `int(48.599999... // 12.15) == 3`,
not 4. The renderer caps at n-1 lines and ellipsizes the last visible
line — even though the box was sized correctly. Spurious ellipsis even
when the measurement was right.

Two-part fix that MUST be in the wrap-renderer:

```python
def _draw_wrapped_text(c, x, y_top, max_w, max_h, text, *, font, size, color):
    text = (text or "").strip()
    if not text:
        return
    c.setFillColor(color)
    c.setFont(font, size)
    line_h = size * 1.35
    # +0.5px tolerance so float drift below n*line_h still counts as
    # room for n lines. n*line_h - 0.0000006 < n*line_h triggers the bug.
    max_lines = max(1, int((max_h + 0.5) // line_h))
    # Use the SAME wrap helper the measurement pass used. The two cannot
    # disagree on line count if they share wrap logic.
    all_lines = _wrap_lines(c, text, max_w, font, size)
    if len(all_lines) > max_lines:
        lines = all_lines[:max_lines]
        last = lines[-1]
        while last and c.stringWidth(last + "…", font, size) > max_w:
            last = last[:-1]
        lines[-1] = (last + "…") if last else "…"
    else:
        lines = all_lines
    y = y_top
    for line in lines:
        c.drawString(x, y - size, line)
        y -= line_h
```

The `+ 0.5` tolerance + shared `_wrap_lines` together guarantee measure
and render agree. Apply this pattern to ANY new free-text PDF that
uses a fixed-budget wrap renderer.

### 3e. The Submit handler wiring

```python
# pages/<submit>.py — inside the Submit button's if-block
with st.status("Submitting...", expanded=True) as status:
    # 1. Write submission row to pin
    pin_ok = append_submission(row)
    if not pin_ok:
        status.update(label="Pin write failed.", state="error")
        st.stop()

    # 2. Render PDF
    pdf_path = build_<app>_pdf(row)

    # 3. Resolve + deliver to channels
    logic_app_url = os.environ.get("LOGIC_APP_URL")
    if not logic_app_url:
        update_submission_delivery(row["submission_id"], "failed", "")
        status.update(label="LOGIC_APP_URL not set — saved but not delivered.",
                      state="error")
        st.stop()

    channels = resolve_channels(row["groundcontrol_id"], row["scope"])
    results = deliver_to_channels(pdf_path, channels, logic_app_url=logic_app_url)

    # 4. Record delivery status
    delivered = [c for c, ok in results.items() if ok]
    update_submission_delivery(
        row["submission_id"],
        "delivered" if len(delivered) == len(channels) else "partial" if delivered else "failed",
        ",".join(delivered),
    )

    # 5. Clean up draft + PDF
    if st.session_state.get(draft_id_key):
        delete_draft(st.session_state[draft_id_key])
    Path(pdf_path).unlink(missing_ok=True)
```

## 3f. CONNECT_API_KEY in PowerShell sessions — BLOCKING gotcha

This bit us May 25 2026 during the transition-PDF QA: ran the redeliver
CLI on the work laptop, got "no submissions matching player" for every
known player, spent ~10 minutes assuming the pin was empty. **The pin
read was failing silently because `CONNECT_API_KEY` wasn't set in the
current PowerShell window.**

Three things conspired:

1. **PowerShell env vars are per-session.** `$env:CONNECT_API_KEY = "..."`
   is scoped to ONE shell window. Open a new terminal tab → it's gone.
   Same in VS Code integrated terminal — each new terminal pane is a
   fresh PowerShell.
2. **`pins.board_connect()` doesn't raise on missing auth.** It returns
   a board object that fails on the actual `pin_read()` call, not on
   construction.
3. **`_pin_read()` catches every exception silently** (`logger.warning`
   that's invisible in production logs by default — see
   `tracker-parquet-pins.md` §5.3) and returns `None`. Caller's
   `load_submissions()` falls back to local CSV which is empty.

Symptom: pin appears empty even though the live app shows the
submission in its View tab.

Verification one-liner — paste into the same PowerShell window before
running the CLI:

```powershell
$env:CONNECT_API_KEY    # blank? you forgot to set it in THIS session
```

If blank, set it:

```powershell
$env:CONNECT_API_KEY = "<the key from the existing Streamlit app's Vars tab>"
```

And re-run the CLI. Submissions appear instantly.

**Better behavior to consider for future CLIs in this pattern**: fail
loud, not silent, when the pin is unreachable. E.g.:

```python
df = load_submissions()
if df.empty and not _pin_was_reached():
    print("ERROR: pin read failed. Did you set CONNECT_API_KEY in this session?")
    sys.exit(2)
```

Not retrofitted to `redeliver_transition.py` yet — flagged as a
follow-up improvement. Until then, the rule is: ALWAYS check
`$env:CONNECT_API_KEY` before assuming the pin is empty.

Both of these MUST be set in the app's Vars tab (Connect UI →
Content → <app> → Vars) BEFORE the app can submit:

| Variable | Purpose | Where it comes from |
|---|---|---|
| `CONNECT_API_KEY` | Pin read/write auth | Same key used by goals pin (inherited) |
| `LOGIC_APP_URL` | Slack delivery endpoint | Full URL in `delivery.md` §"Logic App URL" |

### Public-Azure vs corp-network — what works from which laptop

Important architectural distinction when QAing this pattern outside the
deployed app:

| Endpoint | Where it lives | Reachable from |
|---|---|---|
| Logic App URL (`prod-XX.southcentralus.logic.azure.com`) | **Public Azure cloud** | ANY internet-connected machine with the URL + signing key. Personal laptop included. |
| Posit Connect pins board (`connect2.astros.com`) | **Astros corporate network** | Work laptop only (or via VPN). DNS doesn't resolve from personal laptops. |
| GroundControl2 SQL Server (`GCSQL02.ASTROS.COM`) | Same — corporate | Work laptop only. |

What this enables:
- You CAN build a PDF locally on a personal laptop (pure Python +
  reportlab + a hand-built row dict) and POST it to Slack via the
  Logic App for visual QA. The Slack delivery itself doesn't care
  which laptop sent it.
- You CANNOT read the live submissions pin from a personal laptop to
  validate against real production data. That step needs the work
  laptop.

So for PDF-layout QA: synthetic-text smoke-test → POST to
`#pd-automation-test` from any laptop → eyeball on phone. For
real-data validation: `redeliver_transition.py` on work laptop.

If `LOGIC_APP_URL` is missing the app shows a clear error banner and
the submission still saves to the pin — just skips Slack. So the failure
mode is safe: no data loss.

## 5. Drafts — the deferred-load pattern (BLOCKING)

Streamlit forbids mutating `st.session_state[KEY]` AFTER the widget with
`key=KEY` has instantiated in the current script run. Naive Load-button
handlers that try to set widget state directly throw
`StreamlitAPIException` on every click.

**The canonical fix — two-pass state hydration:**

```python
# Load button (inside banner / expander, anywhere below the widgets):
if st.button("Load draft", key=f"load_{draft_id}"):
    st.session_state.t_pending_draft_load = draft_row.to_dict()
    st.rerun()

# _apply_pending_load() — called ONCE at the top of the script, BEFORE
# any widget instantiates:
def _apply_pending_load():
    row = st.session_state.pop("t_pending_draft_load", None)
    if row is None:
        return
    # Now safe to set every widget-key state, since widgets haven't rendered yet
    st.session_state.t_submitter_name = row["submitter_name"]
    st.session_state.t_player_select = _label_for_gc_id(row["groundcontrol_id"])
    # ... etc ...

_apply_pending_load()  # ← call HERE, before any st.text_input() etc.
```

**Other Streamlit gotchas this pattern also fixes:**

- Never pass both `value=` AND `key=` to the same widget. The `value=`
  is only used on first render before state exists; passing both creates
  stale-state bugs when you later try to programmatically update state.
  Use **key-only state management** on every widget.
- Never set `st.session_state.X` in a selectbox callback if there's a
  widget with `key="X"` later in the same script run. Same rule.
- Tracking "unsaved changes": capture a `_form_signature(row)` tuple
  after every Save, and re-compute on each rerun. Show a yellow pill if
  signatures diverge. See `pd-goals/pages/2_Transition.py` for the
  reference impl.

## 6. Test mode toggle

Every form like this should have a "🧪 Test mode" checkbox that overrides
`resolve_channels()` to return `[(OVERFLOW_CHANNEL, "test")]` only. Keeps
QA out of production channels without requiring a code change.

```python
test_mode = st.checkbox("🧪 Test mode — deliver only to #pd-automation-test")
# ... later, in submit handler:
channels = [(OVERFLOW_CHANNEL, "test")] if test_mode else resolve_channels(...)
```

Default off. Yellow warning banner when on.

## 6b. Redeliver CLI (always ship alongside the cleanup CLI)

Pair the cleanup CLI with a **redeliver CLI** that lets you re-render any
existing submission with the current codebase and re-deliver (or just
build locally). Critical for testing PDF-render changes — coaches don't
want to fill out duplicate submissions to QA layout fixes.

`pd-goals/scripts/redeliver_transition.py` is the canonical pattern (~140
lines). Flags:

| Flag | What |
|---|---|
| `--list` | Show every submission in the pin with submission_id, player, date, status |
| `--player "Name"` | Substring match on player_name. Picks MOST RECENT if multiple. |
| `--submission-id <uuid>` | Exact match by submission_id. Use after `--list` to disambiguate. |
| `--channel C0...` | Override Slack channel ID (default: pd-automation-test). |
| `--no-deliver` | Build PDF locally only, skip Slack. **Most common for manual coach delivery.** |
| `--logic-app-url <url>` | Override `LOGIC_APP_URL` env var. |
| `--output-dir <path>` | Where to write the PDF (default `output/_redeliver/`). |

Workflow (on the machine that has corp network access — usually work laptop):

```powershell
cd <repo>
git pull                                                # get latest PDF code
$env:CONNECT_API_KEY = "<the key>"                      # PER SESSION, see §10
$env:LOGIC_APP_URL   = "<url>"                          # only if delivering

# List what's in the pin
python pd-goals/scripts/redeliver_transition.py --list

# Build locally, no Slack — drag the PDF into Slack manually
python pd-goals/scripts/redeliver_transition.py --player "Drew Brutcher" --no-deliver
```

Don't require app redeploy for this — it's a thin script that reads the
pin and runs the current PDF-rendering code. Use it to validate fixes
against real production data before redeploying the live app.

## 7. Cleanup CLI (always ship this alongside the app)

Every in-app submission pin needs a `scripts/clean_<app>_submissions.py`
from day one. It takes three flags:

| Flag | What |
|---|---|
| `--list` | Print every row in the pin |
| `--clear-all --confirm` | Wipe the pin (no undo) |
| `--delete <uuid> [<uuid> ...]` | Remove specific submissions |

Template: `pd-goals/scripts/clean_transition_submissions.py`. Uses a
public `pin_write_<domain>(df)` helper exposed from the pins module (NOT
the internal `_pin_write`). About 90 lines.

## 8. Cache mechanics — important for browse/view pages

```python
@st.cache_data(ttl=60)
def _cached_view_df():
    return load_submissions()
```

60 seconds is the sweet spot:
- Long enough to survive widget reruns (no re-pin-read on every keystroke)
- Short enough that new submissions appear quickly on other users' views

After running the cleanup CLI, the deployed app's cached view data is
stale for up to 60s per session. No redeploy needed — just wait or hard-
refresh. Pins live outside the app lifecycle.

## 10. What NOT to do

- **Don't skip the test-mode toggle.** Shipping a form without one means every QA cycle spams real coach channels.
- **Don't write to the pin without conforming to canonical columns.** Schema drift is silent and corrupts old rows.
- **Don't call `_pin_write()` directly from scripts.** Expose a public `pin_write_<domain>(df)` helper. Underscores are conventional but it signals "not for external use" for a reason — the helper should validate first.
- **Don't mutate widget-key session state after widgets render.** Use the deferred-load pattern in §5.
- **Don't pass both `value=` and `key=` to widgets.** Pick one (always `key=`).
- **Don't hand-roll the Logic App payload.** Field names (`channel`, `filename`, `pdf`) are BLOCKING. Copy from a working script.
- **Don't register scripts/CLIs in manifest.json unless the deploy needs them.** They run from the work laptop, not on Connect. (We do register them for consistency, but it's optional.)
- **Don't block on `LOGIC_APP_URL`.** Save to pin first, then attempt delivery. Failure to deliver should never lose the submission.
- **Don't use fixed-pixel section heights in the PDF.** Coaches type arbitrary-length answers. Fixed heights either crowd short text or truncate long text with ellipsis. Use the measure-then-draw + spillover pattern in §3c.
- **Don't compute `max_lines = int(max_h // line_h)` without a tolerance.** IEEE float subtraction drifts; use `int((max_h + 0.5) // line_h)`. See §3c float-precision gotcha.
- **Don't duplicate wrap logic between measurement and rendering.** They WILL disagree on line count at boundary cases. Share one `_wrap_lines` helper.
- **Don't assume the pin is empty when a CLI says zero rows.** Check `$env:CONNECT_API_KEY` in THE SAME PowerShell session first. See §3f.
- **Don't ship a redeliver/cleanup CLI without `--no-deliver` and `--list` flags.** Both critical for safe ad-hoc QA without accidental coach-channel sends.
