## 2026-05-27 — Postgame `--level` semantics unified across the codebase

Two-part fix for the asymmetry between postgame CLIs and every other CLI in the
codebase around `--level rok` / `--level dsl`. Plus documentation update locking
in the post-fix invariants.

### What graduated

**Knowledge promoted into `rules/level-codes.md`:**

1. **`--level` matrix table** — every CLI + app uniformly handles `--level rok`
   as FCL/ACL only, `--level dsl` as real DSL R games + DSL Live AB intrasquads,
   `--level rok dsl` as both. Documented as a single canonical matrix at the top
   of the DSL/FCL section.

2. **Postgame's old "intentional bundling" exception is GONE.** Pre-fix,
   `--level rok` bundled FCL+DSL silently on postgame because the script
   SELECTed raw `sv.level_code` (DSL games carry `'rok'` raw) and filtered
   Python-side. Now aliased to `sv.gc2_level_code AS level_code` everywhere.

3. **`--level dsl` Live AB admit-mask** — preseason DSL kids only appear via
   Live AB (`R + level_code='int' + is_int_level=1`), which carry
   `gc2_level_code='int'` (not `'dsl'`). Hitter + pitcher postgame CLIs now OR
   in `(level_code=='int') & (sched_type=='R')` to the level filter when
   `'dsl'` is in level_set. `--level rok` does NOT admit Live AB.

4. **Two-layer separation (BLOCKING, now more prominent)** — Live AB pitches
   never enter any percentile pool. Display layer routes Live AB kid to DSL
   pool for comparison via `is_live_ab` per-row routing; pool DEFINITION
   built strictly via `_build_level_filter` (which gates on
   `gc2_level_code`). Audit-verified clean across all percentile builders.

5. **Litmus test rewritten** to reflect uniform behavior: `--level dsl` empty
   on a DSL-active day = bug; `--level rok` returning DSL kids = bug.

### Methodology notes encoded

Three load-bearing facts captured in `memory/paa-eo-matrix-shipped.md`
+ this entry:

1. **Cross-level PAA/EO aggregation is mathematically correct** because
   `guts.PAA_EO_Position_Calibration` JOIN is keyed on `(pos_id,
   positional, season)` only — no level join. So `paa_cal` +
   `expected_outs` are level-additive and `paa_eo` re-derives as
   `SUM(paa_cal) / SUM(expected_outs)` exactly like the
   `_aggregate_dcbp` within-level logic. Useful precedent for any
   future cross-level reports that touch DCBP-derived metrics.

2. **Per-row coloring against player's current-level pool** is a
   deliberate tradeoff. A Max Holy aggregated row shows combined
   A+/AA stats but colored against AA-only pool. Mild over-color risk
   if prior level was much easier; user accepted explicitly.

3. **Proportional `ax_height` trick** for plottable-paginated tables
   with partial last pages: `ax_height = full_height * (n_rows + 1)
   / (rows_per_page + 1)`, top-anchored at the same y as full pages.
   Keeps row size consistent. Reusable for any plottable-based
   paginated CLI report — note for future similar work.
